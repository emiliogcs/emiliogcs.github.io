pyfgls — Feasible GLS for Python

Feasible GLS for time series regression and for heteroskedasticity of unknown form.

pyfgls implements the feasible generalized least squares (FGLS) estimators of

  • [PG26] Perron, P. and González-Coya, E. (2026). Feasible GLS for time series regression. Journal of Econometrics 258, 106346 — serially correlated errors;
  • [GP24] González-Coya, E. and Perron, P. (2024). Estimation in the presence of heteroskedasticity of unknown form: a Lasso-based approach. Journal of Econometric Methods 13(1), 29–48 — heteroskedasticity of unknown form;

and their combination for time series with both problems ([PG26] Supplement S-4).

The message of both papers is the same: GLS is not a fragile luxury. Done the way they propose, it is consistent in situations where OLS is not, it is (essentially) never less precise than OLS, it is often far more precise, and its confidence intervals have accurate coverage and are shorter. pyfgls packages those procedures with statsmodels-style results, pandas support and the papers' simulation designs.

Install

pyfgls is on PyPI:

shell
pip install pyfgls                    # core
pip install "pyfgls[formula,plot]"    # + formula interface and diagnostic plots
pip install --upgrade pyfgls          # update to the latest release

Requires Python 3.10 or newer; tested on 3.10–3.13 on Linux, macOS and Windows. Core dependencies: NumPy, SciPy, pandas, scikit-learn, joblib. Optional: formulaic (formula extra), matplotlib (plot extra), statsmodels (only used in the test suite).

A virtual environment keeps these dependencies apart from other projects:

shell
python3 -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
python -m pip install --upgrade pip
python -m pip install pyfgls

Check the installation; this prints the installed version:

shell
python -c "import pyfgls; print(pyfgls.__version__)"

Your pip runs on Python 3.9 or older (on macOS, the built-in python3 is 3.9), and older versions of pip do not say that the Python version is the reason. Check with python3 --version, install Python 3.10+ (from python.org, or brew install python@3.12) and use a virtual environment:

shell

4. Robust versus naive intervals

When a regressor responds to past shocks, the textbook GLS variance ([PG26] eq. 27) ignores that the AR filter was estimated and its intervals are too short. The default variance (eq. 29) accounts for it.

python
import pyfgls as pf
from pyfgls.simulate import serial_dgp

# AR(1) errors (rho = 0.5) and a regressor x_t = 0.5 x_{t-1} + v_t + e_{t-1}
# that responds to last period's shock: pre-determined, not exogenous
sim = serial_dgp(200, ar=(0.5,), rho_x=0.5, gamma=1.0, burn=100, random_state=3)
model = pf.SerialFGLS(sim.y, sim.X)
robust = model.fit()  # default: [PG26] eq. (29)
naive = model.fit(cov_type="naive")  # eq. (27): valid for exogenous regressors only
print(f"nonexogeneity_share = {robust.nonexogeneity_share:.3f}")
print(pf.compare([naive, robust], names=["naive", "robust"]))
output

Cross section (random sample) Heteroskedasticity of unknown form LassoFGLS(y, X) [GP24]
Time series with lags of y as regressors Serial correlation SerialFGLS(y, X, lagged_dep_vars=[...]) [PG26] §4.2
Errors known to be MA(1), e.g. 2-step-ahead forecast errors MA(1) with large negative θ SerialFGLS(y, X, ma1=True) (GMA) [PG26] §5

You only want robust standard errors for OLS — pf.benchmarks.ols(y, X, cov_type="HAC") / "HC3" —

FGLS is the general class: serial=None turns off the serial-correlation correction and hetero=None the heteroskedasticity correction, so FGLS(y, X, hetero=None) is the same estimator as SerialFGLS(y, X) and FGLS(y, X, serial=None) the same as LassoFGLS(y, X).

Compared with the usual alternatives:

Instead of Use Why
OLS + HAC standard errors SerialFGLS OLS is inconsistent when the regressors respond to past shocks (pre-determined, not exogenous); FGLS stays consistent, is more precise, and its intervals cover better with persistent errors.
Cochrane–Orcutt SerialFGLS Cochrane–Orcutt estimates the AR filter from OLS residuals and inherits their inconsistency; FGLS estimates it from the Durbin regression.

Time-series regressions with serially correlated errors ([PG26], Section 6)

The concluding remarks of [PG26] translate into the following recommendations.

  1. Use FGLS as the default. In a linear time-series regression with stationary errors, estimate by FGLS with the AR order chosen by BIC and build confidence intervals with the exogeneity-robust variance of eq. (29) — SerialFGLS(y, X).fit() does exactly this. If the regressors happen to be exogenous, the robust correction vanishes asymptotically, so nothing is lost; if they are not, it is what makes the intervals reliable. OLS, by contrast, is generally inconsistent when the regressors react to past shocks, and Cochrane–Orcutt inherits that inconsistency.
  2. Check that the regressors are pre-determined. FGLS needs the regressors to be uncorrelated with current and future innovations (not with past ones). Use the variable-addition LM test of Remark 9, pf.diagnostics.test_predetermined(y, X). If it rejects, add lags of the relevant regressors to the model and refit; if the problem comes from omitted variables that are not observed, an instrumental-variables procedure is needed instead (outside the scope of this package).
  3. Large negative moving-average components need care. When the errors may contain an MA term with a large negative coefficient (typical of multi-step forecast errors), a finite autoregression approximates them poorly and BIC may stop too early, which shows up as intervals that under-cover. If you know the MA structure, use a tailored transformation such as the GMA estimator (SerialFGLS(..., ma1=True)).
  4. Lagged dependent variables. With lags of y among the regressors, OLS is inconsistent under serial correlation; declare them (lagged_dep_vars=["ylag"]) so the AR filter is recovered from the lagged regressors (Section 4.2).
  5. Multi-step predictive regressions. Under rational expectations the h-step forecast errors are MA(h−1) and both OLS and FGLS are consistent; FGLS is more efficient as long as the implied MA process is invertible. If it may be non-invertible, FGLS is only consistent with exogenous regressors — be cautious.
  6. Know your maintained assumptions. The advantages of GLS over OLS with HAC standard errors rest on stationarity, invertibility of the error process and pre-determined regressors. When these are plausible — as they usually are — the gains in precision and in the reliability of inference are substantial. Use check_stationarity=True to screen for unit roots, and watch for NonStationaryWarning (an estimated AR filter with a root near the unit circle).
  7. Heteroskedastic innovations ([PG26] Remark 12). Either keep FGLS for the serial correlation and make the variance heteroskedasticity-robust (cov_type="HC3"), or — recommended — add the Lasso-based weighting of [GP24]: FGLS(y, X) (F-CH). With homoskedastic innovations F-CH is equivalent to correcting for serial correlation only, so there is no cost.

How much does nonexogeneity_share matter? It reports how large the eq. (29) correction is relative to the textbook GLS variance: near 0 the regressors behave as exogenous; large values mean the naive interval would under-cover.

Cross sections with heteroskedasticity of unknown form ([GP24], Section 6)

  1. Lasso-FGLS is a safe replacement for OLS + robust standard errors. In all the designs of [GP24] it was never noticeably worse than OLS (at most a few percent of MSE when there is no heteroskedasticity, because the Lasso then selects nothing and the weights are constant), and it is markedly better when heteroskedasticity is present.
  2. You do not need to know the variance function. It is enough that the candidate covariates z include at least one variable correlated with what drives the variance, plus some non-linear transforms. The Lasso picks what fits the variance pattern in the sample; it need not pick the "true" form, and it does not need to.
  3. Prefer many variables and few transforms. Adding many candidate variables works well; adding many functional forms of the same variable creates near-collinearity and helps little. Trigonometric terms (cos w, cos 2w, i.e. Chebyshev-type terms) are a good flexible choice: LassoFGLS(y, X, transforms=("linear", "trig")) or build your own z with pyfgls.hetero.make_dictionary. The default dictionary {x, x², log x, (log x)², cos x, cos 2x} per regressor follows the paper's simulations.
  4. Always use the bias-corrected robust variance (the default, eq. (8)). The fitted variance function is an approximation, so model-based standard errors are not reliable; the corrected sandwich gives close-to-nominal coverage with intervals that are much shorter than OLS-HC intervals under heteroskedasticity.
  5. Avoid unrestricted parametric WLS when the variance driver is uncertain. The Romano–Wolf WLS estimators (skedastic="wls_s1", "wls_s2") can be much worse than OLS when the true driver is not among their covariates; SVR ("svr") is competitive in MSE but tends to give less accurate coverage. The adaptive Lasso dominates both.

User guide

Data requirements

  • y, X may be NumPy arrays, lists, pandas Series/DataFrame; names and the index are carried into the results. Include a column of ones for an intercept (a warning is issued if there is none; implicit intercepts such as a full set of dummies are recognised).
  • Time order matters for serial-correlation corrections. A pandas index must be sorted and unique; a DatetimeIndex/PeriodIndex with gaps raises TimeIndexError unless allow_gaps=True (lags are then positional, e.g. trading days). Panels (MultiIndex) are not supported.
  • Missing values raise MissingDataError by default; missing="drop" drops leading/trailing rows for time series (interior gaps would corrupt the lags) and any incomplete row for cross sections. Infinite values always raise.
  • Rank-deficient X raises CollinearityError naming the offending columns. Lagged constants, trends and seasonal dummies in the Durbin regression are dropped automatically.
  • Formulas (needs formulaic): pf.FGLS.from_formula("y ~ x1 + np.log(x2) + lag(x1)", data=df, missing="drop"); the intercept is named const.

ar_order Fix the AR order instead of selecting it.
ic "bic" (default, as in [PG26]) or "aic".
kmax Largest order considered: default int(12·(T/200)^¼) (12 at T = 200); "theory" = ⌊(T/ln T)^⅓⌋; or an int. Capped so the Durbin regression uses ≤ 50% of the sample as regressors.

exog Your assumption; only affects notes and the default first-stage correction of FGLS.
ma1 GMA estimator for MA(1) errors (§5).
cov_type "robust" (eq. 29, default), "naive" (eq. 27, exogenous regressors only), "HC0"–"HC3" (eq. 29 with heteroskedasticity weights), "bootstrap" (sieve).

FGLS — both, and the general interface

python
pf.FGLS(y, X, serial="auto", hetero="lasso", z="auto", first_stage_correction=None, ...)

serial ∈ {"auto", "fixed", "ma1", None}, hetero ∈ {"lasso", "svr", "wls_s1", "wls_s2", "known", None}; all SerialFGLS and LassoFGLS options are accepted. The combined fit (F-CH) applies the [GP24] weights to the quasi-differenced regression, with candidate covariates built from the unfiltered regressors. first_stage_correction (default on for pre-determined regressors) adds the eq. (29)-type term for the estimated AR filter to the sandwich variance; in our simulations with non-exogenous regressors it raises the coverage of 95% intervals from 0.78 to 0.94. cov_type: "robust", "HC0", "HC3", "bootstrap".

Reading summary()

print(res.summary()) prints three blocks: a header that describes the fit, the coefficient table, and numbered notes. res.summary(alpha=0.10) gives 90% intervals. Quick example 1 (serial correlation) and Quick example 2 (heteroskedasticity) show typical output.

Header

Line Meaning
Dep. variable Name of y: the Series name, the left-hand side of a formula, or y for arrays.
Method FGLS (serial) ([PG26]), GMA (MA(1)) ([PG26] §5), FGLS (hetero) ([GP24]), F-CH (serial+hetero) (both); OLS when every correction is switched off.

Interpreting nonexogeneity_share

The robust variance of [PG26] eq. (29) is the naive variance (eq. (27)) plus a term that accounts for the estimation of the AR filter. That term is proportional to \(g_j = E[\tilde x_t u_{t-j}]\), which is zero when the regressors are exogenous.

res.nonexogeneity_share reports the average, over coefficients, of the correction relative to the naive variance, and res.serial.nonexogeneity_by_coef gives it per coefficient:

  • ≈ 0 — the regressors behave as exogenous; naive and robust intervals coincide.
  • > 0.1 — the first-stage correction matters; the naive intervals would under-cover.

The robust variance is valid in both cases, so it is always the default. Declaring exog="exogenous" does not change the estimates; it only adds a note to the summary when the share is large.

Lagged dependent variables

When lags of \(y\) are regressors (e.g. a dynamic model \(y_t = \alpha y_{t-1} + \gamma w_t + u_t\) with AR errors), OLS is inconsistent and the Durbin-regression coefficients on lagged \(y\) mix \(\alpha\) with the AR coefficients of the errors. Declare the lagged dependent variables so pyfgls can recover the AR coefficients from the lagged stochastic regressors (the Wallis ratio, [PG26] Section 4.2):

Reproducibility

Some steps of the estimators are random. Fix the seeds below and a fit gives the same numbers every time it is run.

  • Serial correlation only (SerialFGLS, or FGLS(..., hetero=None)): the fit is deterministic. There is nothing to seed except the bootstrap.

  • Heteroskedasticity (LassoFGLS, FGLS): the cross-validation that tunes the adaptive Lasso (and SVR) splits the sample into random folds. Without a seed the selected covariates, and with them the estimates, can change from run to run. Pass random_state= (an int or a numpy.random.Generator) to the model:

    python
    res = pf.LassoFGLS(y, X, random_state=0).fit()

    fold_scheme="blocked" uses contiguous blocks instead of random folds and needs no seed.

  • Bootstrap (fit(cov_type="bootstrap")): pass boot_random_state=; by default it takes the model's random_state. Each replication draws from its own child seed (numpy.random.SeedSequence.spawn), so the result does not depend on n_jobs.

  • Simulated data: every design in pyfgls.simulate takes random_state.

n_jobs only spreads the folds and the bootstrap replications over cores; with a fixed seed the results are the same for any value.

Theory

Serial correlation ([PG26])

Model: \(y_t = x_t'\beta + u_t\) with \(u_t = C(L)e_t\) invertible, so that \(A(L)u_t = e_t\) with \(A(L) = 1 - \sum_{j\ge1}\rho_j L^j\) and \(e_t\) a martingale difference sequence.

Exogenous versus pre-determined regressors

The regressors are pre-determined when \(x_t\) is uncorrelated with current and future innovations, and exogenous when, in addition, it is uncorrelated with past innovations. Many time-series regressors are only pre-determined: they react to past shocks.

Under pre-determinedness alone, OLS is generally inconsistent — its error \(u_t\) contains past innovations that are correlated with \(x_t\). GLS, which works with the innovations \(e_t\) themselves, remains consistent. This reverses the usual advice that OLS is the "robust" choice ([PG26] Section 3).

Estimating the filter

The feasible version needs an estimate of \(A(L)\) that is itself consistent under pre-determinedness. Estimating it from OLS residuals (Cochrane–Orcutt) fails because the residuals inherit the OLS inconsistency. Instead [PG26] use the Durbin regression (eq. (14))

\[y_t = \sum_{j=1}^k \rho_j y_{t-j} + x_t'\beta - \sum_{j=1}^k x_{t-j}'\delta_j + e_{kt},\]

whose regressors are all uncorrelated with \(e_t\). The order \(k\) is chosen by BIC, with every candidate order estimated on the same sample \(t = k_{\max}+1,\dots,T\) so that the criteria are comparable:

\[\mathrm{BIC}(k) = \ln\hat\sigma_k^2 + k\,\frac{\ln(T-k_{\max})}{T-k_{\max}}, \qquad k = 0,\dots,k_{\max},\]

with \(\hat\sigma_k^2\) the mean squared residual of the order-\(k\) Durbin regression. Lagged deterministic terms (constant, trends, seasonal dummies) are collinear with their contemporaneous values and are dropped automatically.

FGLS and its variance

The data are quasi-differenced with \(\hat\rho_1,\dots,\hat\rho_{k^*}\) and OLS is applied (eq. (15)):

\[\tilde y_t = y_t - \sum_{j=1}^{k^*}\hat\rho_j y_{t-j}, \qquad \tilde x_t = x_t - \sum_{j=1}^{k^*}\hat\rho_j x_{t-j}, \qquad \hat\beta = \Big(\sum_{t>k^*}\tilde x_t\tilde x_t'\Big)^{-1}\sum_{t>k^*}\tilde x_t\tilde y_t .\]

Because the filter is estimated, the variance of \(\hat\beta\) has two parts (Theorem 2): the usual GLS term and a correction for the first-stage estimation of \(\rho\), which involves \(g_j = E[\tilde x_t u_{t-j}]\). Under exogeneity \(g_j = 0\) and the correction vanishes (the naive variance, eq. (27)); otherwise it does not, and the robust variance of eqs. (28)–(29) — the default in pyfgls — must be used. Its relative size is reported as nonexogeneity_share.

Lagged dependent variables

If lags of \(y\) are among the regressors, the coefficients on lagged \(y\) in the Durbin regression no longer estimate \(\rho\). Declare them (lagged_dep_vars=[...]) and pyfgls recovers \(\rho_j\) from the ratio of the coefficients of a lagged and a contemporaneous stochastic regressor (Wallis, 1967; [PG26] Section 4.2).

Heteroskedasticity of unknown form ([GP24])

Model: \(y = X\beta + u\), \(E[u\mid X] = 0\), \(\operatorname{Var}(u_t) = v_t\) with an unknown variance function.

Estimating the skedastic function

GLS weights each observation by \(1/v_t\). [GP24] estimate \(\log v_t\) by regressing \(\log\max(\hat u_t^2,\delta^2)\) — the log of the squared OLS residuals, floored to avoid \(\log 0\) — on a set of candidate covariates \(z_t\) with an adaptive Lasso:

  1. a ridge regression gives preliminary coefficients;
  2. each candidate is penalised in inverse proportion to \(|\hat\gamma^{\text{ridge}}_j|^{\psi}\);
  3. the penalty level \(\lambda\) and the exponent \(\psi\) are chosen jointly by cross-validation.

With \(\ell_t = \log\max(\hat u_t^2,\delta^2)\),

\[\hat\gamma = \arg\min_{\gamma_0,\gamma}\ \sum_t\big(\ell_t - \gamma_0 - z_t'\gamma\big)^2 + \lambda\sum_j \frac{|\gamma_j|}{|\hat\gamma^{\text{ridge}}_j|^{\psi}}, \qquad \hat v_t = \exp(\hat\gamma_0 + z_t'\hat\gamma),\]

and the estimator is weighted least squares with weights \(1/\hat v_t\): \(\hat\beta = (X'\hat V^{-1}X)^{-1}X'\hat V^{-1}y\) with \(\hat V = \operatorname{diag}(\hat v_t)\).

The Lasso can handle many candidates, even more than observations, and selects a parsimonious model. If nothing is selected the weights are constant and FGLS reduces to OLS, so nothing is lost under homoskedasticity.

Inference

Because the estimated variance function is only an approximation, pyfgls uses a heteroskedasticity-robust sandwich for the weighted estimator (eq. (6)), with a finite-sample bias correction that inflates the squared residuals by the leverage of the weighted regression and by the degrees of freedom of the skedastic fit (eq. (8)). The resulting intervals have close to nominal coverage and are much shorter than OLS intervals under heteroskedasticity.

The parametric alternatives of Romano and Wolf (2017) ("wls_s1", "wls_s2") and a support-vector regression ("svr") are also available.

Both problems ([PG26] Supplement S-4)

With serially correlated errors whose innovations are heteroskedastic, the two corrections are applied in sequence:

  1. F-C: the serial-correlation FGLS of [PG26];
  2. the adaptive-Lasso skedastic fit of [GP24] on the F-C residuals, with candidate covariates built from the unfiltered regressors;
  3. F-CH: weighted least squares on the quasi-differenced data.

The variance is the bias-corrected sandwich of [GP24] applied to the filtered regressors. pyfgls optionally adds a first-stage term for the estimated AR filter, the analogue of [PG26] eq. (29) for heteroskedastic innovations (first_stage_correction, on by default for pre-determined regressors). Under homoskedastic innovations F-CH is essentially equivalent to F-C.

Implementation choices and open items

Where the papers leave room, pyfgls makes the following choices (all overridable):

  • kmax = int(12·(T/200)^¼); the [PG26] simulations use 12 for T = 200 and 500.
  • Variances are scaled by the effective sample T − k*; normal critical values unless use_t=True.
  • The Lasso degrees of freedom count the intercept; the Romano–Wolf variance uses HC3 OLS residuals (eq. 7).
  • The ridge weights of the adaptive Lasso are re-estimated within each CV fold so the CV error is not flattered by weights that have seen the test fold (cv_weights="full" computes them once).
  • The Lasso path is computed exactly (LARS); coordinate descent did not converge on the highly correlated default dictionary.
  • The first k* observations are dropped (no Prais–Winsten).

Open items for the authors:

  • Combined variance. The Supplement does not write the first-stage term for F-CH; pyfgls adds a heteroskedasticity-robust analogue of eq. (29) by default (coverage 0.94 with vs 0.78 without it for non-exogenous regressors).
  • Lag penalty with many regressors. The eq. (14) BIC penalises only the AR order; with several stochastic regressors it tends to select kmax. ic_penalty="params" is available; the default follows the paper.
  • Small-sample Lasso efficiency. At T = 100–200 our Lasso-FGLS eMSE ratios are 0.03–0.06 above [GP24] Table 1 (e.g. x²: 0.75–0.77 vs 0.70), although WLS-S1/S2, the infeasible GLS and the interval lengths agree with the paper and the T = 400 ratios match; the difference must come from details of the glmnet-based tuning.
  • Multi-regressor Wallis ratio (wallis_regressor): "auto" uses the regressor with the largest |t|; [PG26] reports insensitivity to the choice.
  • Remark 9 test. Read literally (n·R² of the Durbin residuals on X and lagged x), the test rejects correctly specified models whose regressors are pre-determined but not exogenous, because the Durbin residuals are not orthogonal to X and still contain past innovations. test_predetermined therefore uses the variable-addition form n(SSR₀ − SSR₁)/SSR₀ on the innovation scale (residuals and regressors filtered with the Durbin AR filter); simulated size 0.04, power 1.00 against an omitted x_{t−1}. scale="errors" keeps the literal reading.
  • GMA. θ̂ is the exact Gaussian MLE from the residuals of the Durbin regression with k_T = int(4(T/100)^{2/9}) lags (§5), and all T observations are transformed.

Cochrane–Orcutt FGLS for AR(p) errors (two-step by default, or iterated).

The two-step version (the "CO-FGLS" of [PG26] Section 3 and Table 1) estimates the AR coefficients by regressing the OLS residuals on their own lags and then applies OLS to the quasi-differenced data. It is invalid with non-exogenous regressors: the OLS residuals inherit the inconsistency of OLS and so does the estimated filter (in the Table 1 design, rho = 0.8 is estimated with a bias of about -0.17) — use SerialFGLS instead.

With iterate=True the two steps are repeated until the AR coefficients converge; the fixed point is the nonlinear least-squares estimate of the common-factor AR(p) model, which (unlike the two-step version) does not rely on OLS residuals, but it is only valid when the AR(p) error model is correctly specified.

The covariance is the conventional s^2 (Xf'Xf)^{-1} of the last filtered regression.

Variable-addition LM test for missing lags of the regressors ([PG26] Remark 9).

Experimental. Steps: (a) Durbin regression (AR order by BIC) giving beta^D and rho^D; (b) residuals u^D = y - X beta^D; (c) demean; (d) for l = 1, ..., max_lag test whether lags 1..l of the stochastic regressors belong in the model with the variable-addition statistic

output
LM_l = n (SSR_0 - SSR_1) / SSR_0  ~  chi^2(l m)   (m regressors tested),

where SSR_0 and SSR_1 are the residual sums of squares of the auxiliary regression without and with the candidate lags. A rejection suggests adding lags of the regressors to the model (so that they become pre-determined) and refitting.

scale="innovations" (default) runs the auxiliary regression on the innovation scale: u^D and all regressors are filtered with the Durbin AR filter and the lagged u^D enter as nuisance regressors. Under pre-determinedness the filtered residuals are (approximately) serially uncorrelated innovations, uncorrelated with past regressors even when those are not exogenous, so the chi-square approximation holds. scale="errors" uses u^D and the raw regressors directly (the literal reading of Remark 9).

FAQ and troubleshooting

pip install pyfgls says "No matching distribution found". Why? pyfgls requires Python 3.10 or newer, and pip skips releases that do not support the Python it runs on. Older versions of pip do not say that this is the reason. On macOS, the built-in python3 is 3.9. Check with python3 --version, install Python 3.10+ (python.org or brew install python@3.12) and use a virtual environment: python3.12 -m venv .venv && source .venv/bin/activate && python -m pip install pyfgls.

Why not Cochrane–Orcutt? It estimates the AR filter from OLS residuals. When the regressors are only pre-determined, OLS is inconsistent, and so is the filter: in the [PG26] Table 1 design the Cochrane–Orcutt estimate of \(\rho = 0.8\) is biased by about −0.17 and the slope by +0.03, while FGLS based on the Durbin regression is essentially unbiased. pyfgls.benchmarks.cochrane_orcutt is available for comparison.

Why a robust variance for FGLS? Estimating the filter adds variability that the textbook GLS variance ignores whenever the regressors are correlated with past errors ([PG26] eq. (29)). For the heteroskedastic estimator, the fitted variance function is only an approximation, so a sandwich with a bias correction is used ([GP24] eq. (8)).

Isn't OLS with HAC standard errors safer? Only if the regressors are exogenous — otherwise OLS is inconsistent. Even then, GLS can be far more precise and HAC intervals tend to under-cover with persistent errors.

What if there is no serial correlation or heteroskedasticity? BIC selects \(k^* = 0\) and/or the Lasso selects no covariate; you get OLS with valid standard errors.

Can I use panel data? Not yet: a MultiIndex raises a TimeIndexError.

Which warnings and errors can I get, and what do I do about them?

Warning or error What it means What to do
TimeIndexError The index is unsorted, has duplicates, has gaps (dates or periods), or is a panel MultiIndex. Sort it and remove duplicates. For trading-day data pass allow_gaps=True (lags are then positional). Panels are not supported.
MissingDataError Missing or infinite values. missing="drop" drops incomplete rows (for time series only leading and trailing ones, since interior gaps would corrupt the lags). Infinite values always raise.
CollinearityError X is rank deficient; the message names the columns. Drop or combine them (for example a constant plus a full set of dummies).
InsufficientDataError Too few observations for the model. Use a longer sample or a smaller model: fewer regressors, a lower kmax or ar_order, fewer cv_folds.
InputError Other invalid input: shapes, non-numeric data, unknown options. The message names the argument.
NonStationaryWarning A root of the estimated AR filter is on or near the unit circle. The errors may have a unit root: screen with check_stationarity=True, difference the data or respecify the model.
CollinearityWarning Columns were dropped where that is safe (lagged constants and trends in the Durbin regression). Usually nothing; the summary notes list them.
LaggedDependentWarning A regressor equals a lag of y. Declare it: lagged_dep_vars=["ylag"].
SpecificationWarning An unusual specification, such as no intercept. Add a column of ones, unless the omission is intended.
SampleSizeWarning The sample is small relative to the parameters, lags or folds. Expect noisier lag or covariate selection; a smaller kmax, z or cv_folds helps.
WeightWarning The FGLS weights are extreme (a very large max/min variance ratio). Look for outliers; weight_clip=(0.01, 0.99) winsorises the fitted log-variance.
ConvergenceWarning An iterative routine did not converge: the Lasso path, the MA(1) likelihood of GMA, or iterated Cochrane–Orcutt. Check the scaling of the data and the specification before relying on the fit.
ExperimentalWarning The feature is experimental, such as test_predetermined. Results and the API may change.

How do I silence the warnings? All warnings derive from pyfgls.exceptions.PyFGLSWarning: warnings.simplefilter("ignore", pf.exceptions.PyFGLSWarning).
